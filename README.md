# Семестровый проект: сервис бронирования

ДРИП, 2 курс · Разработка веб-интерфейсов · Модули 1–2

Индивидуальный проект, **10 баллов**. Разработайте сервис с каталогом, поиском, выбором предложения, созданием и отменой заявки. Сервер проверяет доступное количество и сохраняет данные. Тему, контент, оформление, структуру кода и порядок работы выбираете самостоятельно.

## Задание

- [Требования](docs/Требования.md) — обязательные результаты R1–R12.
- [30 тем](<docs/Темы на выбор.md>) — варианты предметной области.
- [Данные и API](<docs/Данные и API.md>) — общий контракт.
- [Приёмка](docs/Приёмка.md) — ручные сценарии S01–S18 и unit-тесты U1–U4.
- [Оценивание и защита](<docs/Оценивание и защита.md>) — 40 критериев по 0,25 балла.

ИИ разрешён для объяснений и локальных подсказок; сдаваемую реализацию и отчёт выполняете самостоятельно. Границы помощи — в R12 [требований](docs/Требования.md), служебные инструкции помощникам — в [AGENTS.md](AGENTS.md).

## Запуск основы

Node.js **22.22.2** закреплён в [.nvmrc](.nvmrc); допустимые версии Node/npm — в [package.json](package.json). При установленном nvm:

```bash
nvm install
nvm use
npm ci
npm run dev
```

Без nvm установите указанную версию Node самостоятельно. Откройте адрес из терминала: появится сообщение «TypeScript-модуль подключён. Можно начинать работу.».

В основе есть TypeScript/Vite, линтеры, конфигурация Vitest и пустые модули `src/`. Папки `server/`, `data/`, `tests/` предназначены для вашей реализации. Сервера, прокси к API и предметных тестов пока нет; структуру можно менять.

`npm run check:starter` проверяет основу и собирает её; `npm run preview` показывает последнюю сборку. `npm test` и `npm run check` пока завершаются с `No test files found`. Для готового проекта должен проходить `check`; также нужно добавить проверку типов в `build` и реализовать `start`/`seed` (R9).

## Сдача

Сдайте ссылку на merged PR в основную ветку: тема, проверенный commit, CI, выпуск и известные ограничения. Исходники, lockfile, конфигурации и вымышленный seed входят в Git; зависимости, сборка, рабочие данные и локальные `.env` — в `.gitignore`.

Документация собственного проекта — корневой README и два коротких файла в `docs/` со ссылками из README:

- **README:** назначение и два скриншота; команды, адреса, конфигурация и данные для запуска из чистой копии; Docker/volume, выпуск и Pages; устройство, ограничения, источники и собственный вклад. Добавьте объяснение выбора JSON и пример CSV из контракта.
- **ТЗ:** аудитория, цель, тема, три сценария, категории и `feature`, два критерия удобства, решения и причины их изменений (R1).
- **Проверки:** commit и среда, условия, фактические результаты S/U с логами или скриншотами, два дефекта либо исследованных риска (R11). Отмечайте непроверенное.
