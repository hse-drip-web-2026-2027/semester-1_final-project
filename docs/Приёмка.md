# Приёмка

## S06: последовательность лимита

После seed A/B — `item-a`/`item-b`, ёмкость 5/8. Между шагами данные не сбрасывайте; POST отправляйте с корректными остальными полями. Сохраните id заявок.

| Шаг | Действие | Результат | Остаток A / B |
| --- | --- | --- | --- |
| 0 | Начало | Заявок нет | 5 / 8 |
| 1 | Создать A, quantity 4 | 201, одна заявка a1 | 1 / 8 |
| 2 | Создать A, quantity 1 | 201, одна заявка a2 | 0 / 8 |
| 3 | Создать A, quantity 1 | 409, новая запись не создана, ввод сохранён | 0 / 8 |
| 4 | Создать B, quantity 3 | 201, одна заявка b1 | 0 / 5 |
| 5 | Отменить a1 | 200, a1 cancelled | 4 / 5 |
| 6 | Повторить отмену a1 прямым PATCH | 200, прежняя cancelled; UI может уже скрыть кнопку | 4 / 5 |
| 7 | Создать A, quantity 2 | 201, одна заявка a3 | 2 / 5 |
| 8 | Обновить страницу, перезапустить сервер | Всего **4 созданные заявки**, из них 3 active и 1 cancelled; отказ не создал запись | 2 / 5 |

Активных единиц после последнего шага: A/B — 3/3.

## Unit-тесты

Vitest ищет `tests/**/*.test.ts`, среда Node.js; `test`, `expect`, `vi` импортируются из `vitest`.

| ID | Что проверяется | Случаи |
| --- | --- | --- |
| U1 | Расчёт остатка | Пустые заявки; несколько активных одного itemId; чужой itemId не влияет; cancelled не учитывается; исходный массив не изменён |
| U2 | Допустимость количества | 1 и 5; 0, дробное, 6; ровно остаток; превышение остатка; нулевой остаток |
| U3 | Внешний ввод | Пустое значение, неверный тип, корректное значение после разрешённого преобразования; неизвестное обязательное значение |
| U4 | API-клиент с mock | Ошибочный HTTP-ответ и отклонённый транспорт не превращаются в успешный результат; успешный ответ корректно разобран |

Импортируйте реализацию из исходников, проверяйте значения/состояние, восстанавливайте подмены. Не копируйте расчёт в тест и не подменяйте его mock. Число `it` свободное; пустые тесты, только `todo`, `.only` и `passWithNoTests` не подтверждают выполнение.

Для S16 зафиксируйте падение при временной ошибке правила и успех после восстановления, а также неуспешный/исправленный CI. В отчёте разберите два дефекта либо исследованных риска по R11. Будьте готовы объяснить, что ловит тест и что остаётся за его пределами; ручные сценарии дополняют unit-проверки.
